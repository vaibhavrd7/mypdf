# MyPDF SEO and Google indexing checklist

The production build prerenders the home page, all image and PDF tool pages, and every legal and information page. Each page gets its own HTML title, meta description, canonical URL, Open Graph title and description, useful page copy, internal links, and JSON-LD. The build also writes `robots.txt` and a root-level `sitemap.xml` containing only canonical production URLs.

## Before deployment

1. Open [Google Search Console](https://search.google.com/search-console/) and add the exact public site as a property after the domain is deployed. Verify ownership using the provided HTML meta tag or DNS record.

2. Choose and deploy the public HTTPS domain you intend to keep. Search engines cannot index the local `localhost` preview.
3. Set `SITE_URL` to that exact origin (for example `https://www.example.com`) in the static site's build environment. Do not add a trailing slash.
4. If using Google Search Console's HTML tag verification, set `GOOGLE_SITE_VERIFICATION` to the token value Google gives you. Rebuild and deploy, then complete verification in Search Console. The token is optional for local work. For an existing Render Blueprint, add this variable in the service's Environment page; Render does not prompt again for new `sync: false` values when syncing an existing Blueprint.
5. If you use the Render blueprint, change `SITE_URL` and the matching API/frontend origins in `render.yaml` if the generated hostnames or your custom domain differ from the defaults.
6. Deploy and check these public URLs in a browser: `/`, `/robots.txt`, `/sitemap.xml`, `/jpg-to-webp`, `/png-to-webp`, `/webp-to-jpg`, `/jpg-to-png`, `/compress-image`, and `/resize-image`. Each page should load over HTTPS and have its own content and canonical URL.

## Submit to Google

1. Add the deployed domain as a property in [Google Search Console](https://search.google.com/search-console/) and verify ownership. A Domain property uses DNS verification; a URL-prefix property can use the HTML tag configured above.
2. In Search Console, open **Sitemaps**, submit `sitemap.xml`, and check for fetch or parsing errors.
3. Use **URL Inspection** on the home page and each tool URL. Run **Test live URL**; if accessible and indexable, choose **Request indexing** for the most important pages.
4. Check the Page indexing and Performance reports over time. Recrawling and indexing can take days or weeks, and submission is a discovery signal, not a guarantee of inclusion or ranking.

## Keep pages useful

- Keep each tool's instructions and answers specific to the format or operation. Update `client/src/seoContent.js` when behavior changes.
- Add only public, working canonical URLs to the sitemap. Do not list preview, query-string, or duplicate URLs.
- Keep internal links between relevant tools and make sure every important page is reachable from the home page.
- Do not add fake reviews, claims, or keyword-stuffed text. Structured data must match the visible page.
- Add new routes to `client/src/tools.js`, `client/src/seoContent.js`, and the route output generated by `client/scripts/prerender.mjs` (the latter enumerates the tool list automatically).

Google's official references: [JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [build and submit a sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [request a recrawl](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).
